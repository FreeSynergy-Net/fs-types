Trait `Records` (`limits`, `shape`, `find`, `get`, `groups`, `generation`; boxed futures, not `Send`, usable as `dyn Records`), closed query forms (`RecordQuery`, `Condition`, `Sort`), answers as the asking person (`RecordView` with hidden fields and no value, lock, `may`, group; `RecordPage` with cursor), `Shape` (groupings, orders), `GroupSet`, `Limits` (size and time limits as settings: the program gives the default, the ceiling is the instance's, `Limits::admit` refuses a value above it, `Limits::clamped(ceiling)`, `within`), `MemoryRecords` (double for tests), codes `RecordsCode` (16, `records-error-*`). Nachzug 17.11.: the JMAP filter tree in `RecordQuery` (`Filter`: And, Or, Not = none of, Xor = exactly one; `position`; limits `filter_nodes_max` 64 / `filter_depth_max` 8; a record the person may not read is never counted, never takes a position; a leaf on a hidden field is always false), search kinds (`SearchKind` seven: complete, open, cancellable, deadline, enough, live, relevant; per data type a `SearchPolicy` in `Shape.search`; `relevant` is refused unless allowed and then `unsupported`, the double computes no relevance), `Records::changes` (`cannot-calculate-changes` instead of a silent empty answer), honest totals (`total` or `total_estimated` with `estimate_kind`, never both; snippets only from readable fields); `RecordsCode` has 23 codes.
