## 0.0.4

Released 2026-11-18.

- New crate `fs-records` (in this workspace; version = repository version, no tag of its own): the one way every program lets a frontend READ its records (ADR 0087 Nachtrag, stage E3, trait-delta F1). Trait `Records` (`limits`, `shape`, `find`, `get`, `groups`, `generation`; boxed futures, not `Send`, usable as `dyn Records`), closed query forms (`RecordQuery`, `Condition`, `Sort`), answers as the asking person (`RecordView` with hidden fields and no value, lock, `may`, group; `RecordPage` with cursor), `Shape` (groupings, orders), `GroupSet`, `Limits` (size and time limits as settings: the program gives the default, the ceiling is the instance's, `Limits::admit` refuses a value above it, `Limits::clamped(ceiling)`, `within`), `MemoryRecords` (double for tests), codes `RecordsCode` (16, `records-error-*`). Nachzug 17.11.: the JMAP filter tree in `RecordQuery` (`Filter`: And, Or, Not = none of, Xor = exactly one; `position`; limits `filter_nodes_max` 64 / `filter_depth_max` 8; a record the person may not read is never counted, never takes a position; a leaf on a hidden field is always false), search kinds (`SearchKind` seven: complete, open, cancellable, deadline, enough, live, relevant; per data type a `SearchPolicy` in `Shape.search`; `relevant` is refused unless allowed and then `unsupported`, the double computes no relevance), `Records::changes` (`cannot-calculate-changes` instead of a silent empty answer), honest totals (`total` or `total_estimated` with `estimate_kind`, never both; snippets only from readable fields); `RecordsCode` has 23 codes. Feature `conformance` (never in `default`): `RecordsSuite` (22 rules), `MemoryBench`, 26 bench mutants (`fs_conformance::prove`). Uses `fs_types::coded`, `TypeDescription`, `PageCursor`; no new third-party dependency outside the feature (`async-trait` behind it). Decision 85/86 (c0, 18.11.2026): `RecordView::may` and the new `Shape::may` (commands of the type as a whole: `create`, `import` ...) name ONLY rights, independent of `CommandDescription::supported` and of the lock; suite rule `records.may-rights-only`, bench mutants `may-by-supported`, `may-ignores-rights`, `may-dropped-when-locked`, `type-may-ignores-rights`. Breaking for foreign struct literals: `Shape` has the new required field `may` (a literal `Shape { ... }` needs `may: vec![]`); known user: fs-components `crates/fs-components-catalog/tests/support/tasks_catalog.rs:167` (branches probe-fs-components-catalog-3, forms-accepts-choose-2), to be adapted at the pin lift. The rule `records.estimate-honest` checks pages against the limits the provider declares (`Records::limits`), not the default. Written with the help of Claude (Anthropic).
- Auf Deutsch: Neues Crate `fs-records` (Lesen der Datensätze jedes Programms über EINE Schnittstelle `Records`: Filter, Sortierung, Seiten, Gruppierung, Auswahl der Felder, immer als die fragende Person; nicht lesbare Datensätze fehlen, nicht lesbare Felder sind als verborgen gelistet und ohne Wert); Grenzen für Größe und Zeit sind Einstellungen (Voreinstellung vom Programm, Obergrenze von der Instanz; ein Wert darüber wird abgelehnt); `MemoryRecords` für Tests; Feature `conformance` (nie in `default`) mit der Prüfreihe `RecordsSuite` (22 Regeln) und 26 Prüf-Mutanten. Entscheid 85/86 (c0, 18.11.2026): `RecordView::may` und das neue `Shape::may` (Befehle der Datenart als Ganzes: `create`, `import` ...) nennen NUR Rechte, unabhängig von `CommandDescription::supported` und vom Schloss (ein Befehl mit Recht, aber noch nicht unterstützt, steht drin; ohne Recht nie); Prüfregel `records.may-rights-only`, Mutanten `may-by-supported`, `may-ignores-rights`, `may-dropped-when-locked`, `type-may-ignores-rights`; Bruch für fremde Struct-Literale: `Shape` hat das neue Pflichtfeld `may` (ein `Shape { ... }` braucht `may: vec![]`), bekannter Nutzer fs-components `tasks_catalog.rs:167` (G7-Bauer beim Pin-Lift); `records.estimate-honest` prüft gegen die vom Anbieter genannten Grenzen (`Records::limits`), nicht gegen die Voreinstellung. Geschrieben mit Hilfe von Claude (Anthropic).

## 0.0.3

Released 2026-11-17.

- New basic types, appended to `BasicType` (Cap'n Proto ordinals only appended, nothing renumbered): `integer` (@17, whole number with sign, 64 bit), `duration` (@18, RFC 8984 duration: `P1W`, `P1DT2H30M`, `PT0.5S`; no years or months, units kept as written), `flag` (@19, yes/no, canonical `true`/`false`), `whole` (@20, whole number from 0 up, negatives give `OutOfRange`). Rust types `Integer`, `Duration`, `Flag`, `Whole` (module `number`, `duration`), all `BasicValue`s and registered in `BasicRules`; new `TypeProblem` codes `number.bad`, `duration.bad`, `flag.bad` (appended). A reader of an older schema reads the new kinds as `unknown` (plain text). A duration with hours and seconds but no minutes (`PT1H30S`, not RFC 8984) is read and written as `PT1H0M30S`; a fraction of seconds has at most 9 digits (our limit). Users waiting for them: fs-setting (`flag`, `whole`), fs-forms/fs-tasks (`integer`, `duration`).
- `Date::plus_days(i64) -> Option<Date>` and `Date::days_until(&Date) -> i64`: day arithmetic through `chrono` (no own calendar rules); an out-of-range result is `None`, never a panic; a date stays a date (no zone, no clock). For fs-tasks (due dates).
- To 0.0.2: the short names A1 to A6 in its section mean the conditions of the review of `fs-conformance`; they are written out in `crates/fs-conformance/README.md` (section "Conditions of the first review"). Zu 0.0.2: die Kürzel A1 bis A6 im Abschnitt 0.0.2 sind die Auflagen der Prüfung von `fs-conformance`; ausgeschrieben im README des Crates.
- Breaking: `TypeProblem` is now `#[non_exhaustive]`, and `BasicType` (left as the schema compiler generates it, so not marked) has new kinds. An exhaustive `match` on either stops compiling when the pin is raised and needs a `_` arm. Two known places break: fs-calendars (main c543bcb, `crates/fs-calendars-app/src/frontend_types.rs:101-123`, `type_problem` matches `TypeProblem` exhaustively) and fs-components (branch `unreviewed/probe-fs-components-catalog-2`, `crates/fs-components-catalog/src/accepts/slot.rs:90-110`, exhaustive `match` on `BasicType`). Checked without a match on either type: fs-interfaces, fs-objects, fs-rpc, fs-tasks.
- Additive except for the `non_exhaustive` change above: no existing signature, order or ordinal changed.
- `Date::plus_days` returns `None` when the result lies outside the years 0000 to 9999 (the years `Date::parse` reads), so every result can be written and read again. `coded.rs` and `fs-conformance` code untouched (README only). Written with the help of Claude (Anthropic).
- Auf Deutsch: Neue Grundtypen, an `BasicType` angehängt (Ordinale nur angehängt): `integer` (@17, ganze Zahl mit Vorzeichen, 64 Bit), `duration` (@18, RFC-8984-Dauer: `P1W`, `P1DT2H30M`, `PT0.5S`; keine Jahre/Monate, Einheiten bleiben wie geschrieben), `flag` (@19, Ja/Nein, kanonisch `true`/`false`), `whole` (@20, ganze Zahl ab 0, Negatives = `OutOfRange`). Rust-Typen `Integer`, `Duration`, `Flag`, `Whole`, alle `BasicValue` und in `BasicRules` eingetragen; neue `TypeProblem`-Codes `number.bad`, `duration.bad`, `flag.bad` (angehängt); ein Leser des alten Schemas liest die neuen Arten als `unknown` (einfacher Text). Eine Dauer mit Stunden und Sekunden ohne Minuten (`PT1H30S`, kein RFC 8984) wird gelesen und als `PT1H0M30S` geschrieben; Sekundenbruch höchstens 9 Stellen (eigene Grenze). Wartende Nutzer: fs-setting (`flag`, `whole`), fs-forms/fs-tasks (`integer`, `duration`). `Date::plus_days` und `Date::days_until`: Tagesrechnung über `chrono`, Überlauf = `None`, kein Panic, Datum bleibt Datum (keine Zone, keine Uhrzeit). Breaking: `TypeProblem` ist jetzt `#[non_exhaustive]`, und `BasicType` (bleibt, wie der Schema-Compiler ihn erzeugt, nicht markiert) hat neue Arten; ein erschöpfendes `match` auf eines von beiden kompiliert beim Heben des Pins nicht mehr und braucht einen `_`-Arm. Zwei bekannte Stellen brechen: fs-calendars (main c543bcb, `crates/fs-calendars-app/src/frontend_types.rs:101-123`, `type_problem` matcht erschöpfend auf `TypeProblem`) und fs-components (Zweig `unreviewed/probe-fs-components-catalog-2`, `crates/fs-components-catalog/src/accepts/slot.rs:90-110`, erschöpfender `match` auf `BasicType`); ohne match auf diese Typen geprüft: fs-interfaces, fs-objects, fs-rpc, fs-tasks. `Date::plus_days` gibt `None`, wenn das Ergebnis außerhalb der Jahre 0000 bis 9999 liegt (die Jahre, die `Date::parse` liest), damit jedes Ergebnis geschrieben und wieder gelesen werden kann. Sonst rein additiv; `coded.rs` und `fs-conformance`-Code unverändert (nur README). Geschrieben mit Hilfe von Claude (Anthropic).

## 0.0.2

- New module `fs_types::coded`: `ErrorCode` (trait: stable codes of one crate, `PREFIX`, `ALL`, `as_str`), `Coded<C>` (a code with typed parameters `Param::Text` / `Param::Number`, `with_text`, `with_number`, `with_param`), `Code` (the same code with its enum erased), `message_key`. A failure is a code with parameters, never a sentence (ADR 0057). Additive: nothing existing changed; no new dependency. Users: fs-conformance, fs-starter, fs-setting (their stand-ins `coded_stub` go away in their next change).
- New crate `fs-conformance` (in this workspace; version = repository version, no tag of its own): the frame of every conformance run (`run`, `prove`, `Mutant`, `Report`). It stands only as a dev-dependency, in a `*-testdata` crate, or optional behind the feature `conformance` (never in `default`). It replaces its own copy of the codes (`fault.rs`) by `fs_types::coded`. New codes `mutant-id-invalid` and `duplicate-mutant` (`prove` checks mutant ids), doc hint on `dyn` fixture types, README (written with the help of Claude (Anthropic), as the crate READMEs say). Rules A1-A4 and A6 are in; A5 (consumer gate) is not part of this version. Released 2026-11-17; all crates of the workspace inherit version 0.0.2 (version = tag). `clippy.toml`: `MessageFormat` is a valid doc identifier.
- Auf Deutsch: Neues Modul `fs_types::coded` (`ErrorCode`, `Coded<C>`, `Code`, `Param`, `message_key`): ein Fehler ist ein Code mit typisierten Parametern, nie ein Satz (ADR 0057); rein additiv, keine neue Abhängigkeit; Nutzer: fs-conformance, fs-starter, fs-setting. Neues Crate `fs-conformance` (Rahmen jedes Konformitätslaufs: `run`, `prove`, `Mutant`, `Report`); steht nur als dev-dependency, in einem `*-testdata`-Crate oder `optional` hinter dem Feature `conformance` (nie in `default`); nutzt statt der eigenen Kopie `fault.rs` jetzt `fs_types::coded`; neue Codes `mutant-id-invalid`, `duplicate-mutant`; README. Rules A1-A4, A6 sind enthalten, A5 (Verbraucher-Gate) noch nicht. Geschrieben mit Hilfe von Claude (Anthropic). Alle Crates des Workspace erben die Version 0.0.2 (Version = Tag); Release 2026-11-17.
